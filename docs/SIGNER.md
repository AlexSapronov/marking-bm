# Windows-подписант с реальным КриптоПро / Рутокеном

Подписант использует два файла из **одного и того же коммита**:

- `signer/Start-Signer.ps1` — HTTPS, проверка SHA-256 задания, Bearer-токен в памяти и heartbeat;
- `signer/Sign-Payload.vbs` — локальное создание и проверка CAdES-BES через `cscript.exe` / Windows Script Host.

На реальном компьютере проверено: CAdESCOM через VBScript находит сертификат, назначает его в `CPSigner.Certificate` (без `Set`), создаёт настоящую откреплённую CAdES-BES подпись и успешно проверяет её. Однако **полный связанный подписант, прикреплённая подпись для авторизации и серверный обмен ещё требуют локальной проверки**.

## Почему VBScript

На некоторых Windows установках прямые вызовы CAdESCOM в PowerShell падают на `ComRuntimeHelpers.GetTypeAttrForTypeInfo` с `NullReferenceException`. Обход через `InvokeMember` позволяет найти сертификат, но при присваивании `CPSigner.Certificate` возникает ошибка COM. На той же машине VBScript штатно подписал и проверил данные. Поэтому только криптография выполняется через `cscript.exe`.

## Установка на Windows

Скачайте оба файла из одной ветки или конкретного коммита в каталог `%USERPROFILE%\marking-bm-signer`, запустите обычный Windows PowerShell под тем же пользователем, которому установлен сертификат в `CurrentUser\My`. Не нужно запускать от администратора. КриптоПро и Рутокен должны быть уже установлены и доступны.

Для примеров замените `THUMBPRINT` на 40-символьный отпечаток сертификата, а `SERVER` на реальный HTTPS URL marking-bm:

```powershell
cd "$env:USERPROFILE\marking-bm-signer"
powershell.exe -NoProfile -File .\Start-Signer.ps1 -Server "https://SERVER" -Thumbprint "THUMBPRINT" -Diagnose
```

`-Diagnose` выполняет локальную проверку **откреплённой и прикреплённой** CAdES-BES. Не вводится серверный токен, нет запросов в ЧЗ, нет оплачиваемых операций. Возможен штатный запрос PIN/касания Рутокена.

Вначале повторите диагностику несколько раз, затем после блокировки и разблокировки Windows. Убедитесь, что PIN/касание работают так, как требуется для вашего рабочего процесса. Обратите внимание: в прежних тестах успешно подтверждена только откреплённая подпись; прикреплённая подпись проверяется этим обновлённым сценарием впервые.

## Разовое подключение к серверу

```powershell
powershell.exe -NoProfile -File .\Start-Signer.ps1 -Server "https://SERVER" -Thumbprint "THUMBPRINT" -Once
```

Программа скрыто запросит **отдельный токен подключения Windows-подписанта** (`BM_SIGNER_TOKEN`). Не передавайте его в параметрах командной строки, не включайте в логи или скриншоты. Токен для рабочего сервера задаётся в защищённом `/etc/marking-bm.env`; отпечаток сертификата должен совпадать с `BM_SIGNER_THUMBPRINT`.

`-Once` посылает heartbeat, читает максимум одно уже существующее задание и завершает работу. При наличии задания подписывает его реальным CryptoPro CAdESCOM, локально проверяет подпись и отправляет её в API. Не инициируйте платные заказы для этого теста.

Для длительной работы уберите `-Once`; процесс опрашивает сервер каждые 5 секунд, пока PowerShell запущен. Вкладка браузера не нужна. ПК должен оставаться включённым, пользовательская сессия и Рутокен должны быть доступны.

## Протокол и безопасность

- HTTPS, выделенный bearer-токен, независимо от сессий сотрудников. Токен запрашивается скрыто после проверки наличия сертификата и в `-Diagnose` не нужен.
- Сервер выдаёт тип задания, внутренний ID, одноразовую аренду, Base64 точных байтов, SHA-256, нужный отпечаток и флаг `detached`.
- Для авторизации `auth_true`/`auth_oms` используется **прикреплённая** CAdES-BES, для остальных заданий **откреплённая**. Локальная проверка подписи выполняется в VBScript, внешняя проверка со стороны ЧЗ происходит после отправки сервером.
- PowerShell сверяет SHA-256 байтов до подписания, тип, отпечаток и формат подписи, а затем передаёт payload в дочерний `cscript.exe` **через стандартный ввод в памяти**. Вернувшаяся CMS-подпись читается из stdout; никакие файлы с payload, CMS, PIN или ключом не создаются.
- PIN и закрытый ключ обрабатываются только штатным КриптоПро/Рутокеном. Скрипты не сохраняют PIN, не экспортируют закрытый ключ и не инициируют внешние операции самостоятельно.
- При ошибке подписи сервер получает статус, требующий внимания; задания и повторные отправки контролируются серверной очередью. Тексты секретов и подписи в логи не выводятся.

## Ограничения

На некоторых корпоративных ПК запуск PowerShell/VBScript регулируется политиками IT. Не меняйте политику самостоятельно. Фоновая работа, запрос PIN и доступность сертификата при блокировке пользователя зависят от политики Windows и конкретного Рутокена. При выключенном компьютере подпись недоступна, но задания остаются в очереди.

PR с этим кодом держать открытым до реального успешного `-Diagnose` для обоих форматов и отдельной проверки `-Once` (heartbeat) с реальным сервером; в Linux среде нельзя воспроизвести КриптоПро и физический токен.

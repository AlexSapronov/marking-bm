# Windows-подписант без административных прав

`signer/Start-Signer.ps1` — отдельный процесс PowerShell под обычной учётной записью администратора маркировки. Он использует уже установленный `CAdESCOM` и сертификат в хранилище текущего пользователя. Установка драйверов, КриптоПро и изменение системной политики скриптом не выполняются.

## Локальный PoC

Откройте PowerShell от обычного пользователя:

```powershell
powershell.exe -NoProfile -File .\Start-Signer.ps1 -Server https://marking.internal -Thumbprint YOUR_CERTIFICATE_THUMBPRINT -Diagnose
```

Введите отдельный токен подключения подписанта. Скрипт проверит наличие действующего сертификата с закрытым ключом, подпишет локальную диагностическую строку и проверит CAdES. В ЧЗ никаких запросов, заказов и документов при `-Diagnose` не отправляется.

Зафиксируйте: прошла ли подпись/проверка, запрашивались ли PIN/касание, доступна ли повторная подпись без вмешательства, что происходит после извлечения/установки токена. Повторите несколько раз, затем после блокировки/разблокировки Windows. Это и есть проверка возможности автоматической работы на конкретном Рутокене. Она **не выполнена разработчиком в Linux-среде**.

Если запуск скриптов запрещён корпоративной политикой, согласуйте с IT разрешённый способ запуска/подпись скрипта. Не меняйте политику компьютера и не устанавливайте компоненты самостоятельно.

## Работа

```powershell
powershell.exe -NoProfile -File .\Start-Signer.ps1 -Server https://marking.internal -Thumbprint YOUR_CERTIFICATE_THUMBPRINT
```

Секрет подключения запрашивается скрыто и остаётся только в памяти процесса. Не передавайте его параметром командной строки. PIN не хранится, не передаётся серверу и вводится только в штатном окне провайдера.

Для одноразового прохода добавьте `-Once`. Процесс не требует открытой вкладки браузера. При разрешении корпоративной политики можно создать задачу Планировщика Windows «При входе текущего пользователя», без повышения привилегий, с интерактивным запуском для ввода токена подключения. Скрипт не обещает работу при выключенном ПК или невозможности показать PIN-диалог.

## Протокол

- HTTPS; отдельный Bearer-токен, не связанный с username-сессиями.
- Сервер отдаёт только ранее созданные задания разрешённых типов: авторизация ГИС МТ/СУЗ, эмиссия, отчёт о нанесении, АТК, согласованная трансформация.
- Задание содержит внутренний ID, одноразовую аренду, Base64 точных байтов, SHA-256, ожидаемый отпечаток и формат подписи.
- Для авторизации подписываются байты challenge `data` с прикреплённой подписью. Для документов — точные UTF-8 байты неизменяемого payload и откреплённый CAdES-BES.
- Подписант проверяет хеш, тип и сертификат, выполняет локальную проверку созданной подписи и возвращает результат с арендой. Сервер проверяет ID/аренду/хеш/ожидаемый сертификат и принимает ответ однократно. Проверку УКЭП при внешней отправке выполняет ЧЗ; сервер Linux не имитирует проверку ГОСТ.
- Истёкшая аренда подписи безопасно выдаётся заново: сама подпись не отправляет документ в ЧЗ. Отправкой занимается серверная outbox-очередь.
- Ключ не экспортируется. Полные payload, CMS, PIN и секрет подключения не выводятся в логи.

## Ограничения

Работоспособность `CAdESCOM`, лицензия, доступ к user-store, политика PIN и фоновая работа зависят от установленного окружения. Наличие работающего браузерного плагина само по себе не доказывает доступность COM из PowerShell. При недоступности COM нужен отдельный проверенный браузерный путь на официальном CryptoPro plug-in; он не подменён фиктивной подписью и не заявляется готовым. До успешного PoC очередь остаётся в ожидании подписи.

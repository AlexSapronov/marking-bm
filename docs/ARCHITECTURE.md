# Хранение и переходы состояний

FastAPI обслуживает русский HTML/JS-интерфейс и JSON API. Один фоновый обработчик в том же сервисе исполняет долговечную outbox-очередь. SQLite работает в WAL, мутации и резервирование выполняются через `BEGIN IMMEDIATE`. Для внутренней команды и умеренных объёмов такой стек сокращает инфраструктуру и обеспечивает сериализацию резервов. Сетевые вызовы не удерживают транзакцию записи; актуальность документов проверяется по revision. Формирование PDF атомарно с сохранением снимка и файла, но независимо от уже сохранённого ответа СУЗ.

## Сущности

| Сущность | Назначение |
|---|---|
| `users`, `sessions`, `login_attempts` | Включение username, хеши случайных серверных сессий, CSRF, защита административного входа |
| `suppliers` | Общий справочник и канонический ID после слияния |
| `documents`, `lines` | Владелец, поставщик, revision, этапы; фиксированный состав накладной |
| `catalog`, `pn_map` | Глобальный GTIN→ТН ВЭД и известные PN |
| `codes` | Полный сырой КМ, cis, serial, исходная операция, статус ЧЗ и отдельное локальное назначение |
| `assignments` | История количества/PN/документа; уникальный активный резерв одного КМ |
| `artifacts` | Неизменяемые PDF в ZIP, Excel, исходные файлы, SHA-256, снимок состава и номер версии |
| `operations`, `receipts` | Точный неизменяемый payload/hash, подпись, внешний ID, квитанции, долговечные состояния |
| `batches`, `batch_docs` | Точный выбранный состав партии и независимые группы поставщиков |
| `atks`, `atk_versions` | Код из ЧЗ, полный ТН ВЭД, версии состава |
| `transformations` | Точные КМ, инициатор, согласование, причина и связь с внешней операцией |
| `audit` | Username, время и изменения; UPDATE/DELETE запрещены триггерами |

PDF и остальные файлы хранятся BLOB в той же БД, чтобы snapshot backup включал согласованные версии. Это осознанный выбор для одного VPS и умеренных объёмов. Файлы не пересоздаются при скачивании. Нужен мониторинг диска; очистки истории нет.

## Накладная

| Состояние | Допустимое действие и следующий этап |
|---|---|
| `draft` | Импорт/правка/подтверждение → явный заказ |
| `receiving` | Получение всех заказанных кодов; повторная эмиссия запрещена |
| `label_error` | Коды сохранены, ошибка PDF видна; разрешена корректировка состава |
| `ready` | Актуальная версия ZIP; правка с новой версией или передача поставщику |
| `transferred` | Передана актуальная версия; правка сбрасывает отметку, подтверждение нанесения запускает отдельный отчёт |
| `reporting` | Изменение назначений запрещено; ожидание успешной квитанции и `APPLIED` |
| `reported` | Отчёт принят; ожидание всех отчётов группы или трансформации для дополнения |
| `aggregating` | Отдельный АТК на полный ТН ВЭД, только подтверждённые внешние результаты |
| `done` | Доступны итоговые Excel; старый состав не редактируется |
| `archive` | Через шесть календарных месяцев после завершения; файлы доступны |
| `repack` | Восстанавливаемый промежуточный этап после изменения разбивки; обработчик продолжит резервирование |

`EMITTED` / `APPLIED` — статусы ЧЗ, а не состояния workflow. `free` / `reserved` / `reporting` / `aggregated` / `removed_review` — отдельные локальные состояния КМ. После `APPLIED` триггер БД запрещает изменение сырого кода, PN, количества, ТН ВЭД и документа нанесения.

## Внешняя операция

| Состояние | Поведение |
|---|---|
| `signing` | Ожидает Windows-подписант |
| `leased` | Одноразовая аренда подписи; истёкшую аренду можно переиздать |
| `queued` | Подпись сохранена; перед отправкой повторно проверяются реальные состояния |
| `preflight_blocked` | Запрос мутации ещё не начинался; допустима повторная предварительная проверка |
| `dispatching` | Зафиксирован переход до внешнего вызова; на рестарте → `unknown` |
| `submitted` | Внешний ID сохранён; разрешены проверки результата |
| `done` | Получена квитанция и проверено фактическое состояние |
| `unknown` | Потерян ответ отправленной операции; никакой слепой повторной мутации |
| `blocked` | Явная ошибка/несовпадение; сохраняются исходные данные и необходимость проверки |

Заказ, отчёт и АТК имеют уникальный `op_key`; повторный клик не создаёт вторую операцию. Поля payload/hash неизменяемы триггером. Внешний ID/ответ сохраняется до последующего разбора и формирования PDF. При частичном получении кодов следующий расходующий запрос возможен только после однозначного сохранения предыдущего блока.

Для передаваемых отчётов источник AI 30 — snapshot последнего ZIP, а не исходный Excel. При смене разбивки освобождаются только подтверждённые `EMITTED`. Для включения в АТК источник поставщика — документ фактического нанесения. Изъятие из АТК не делает `APPLIED` свободным.

## Безопасность

Обычная авторизация намеренно не подтверждает личность. Но владение документом проверяется во всех серверных методах, доступ к админке и подписанту независим. Групповой файл АТК/RESULT, содержащий документы нескольких username, доступен администратору и роли «Логист». Бренд-менеджер сохраняет доступ только к своим документам и подходящим файлам. Поиск кандидатов трансформации возвращает минимальные сведения о подходящих КМ того же поставщика.

Секреты не помещаются в Git. Админский хеш и секрет подписанта задаются внешней конфигурацией, токены ЧЗ сохраняются в отдельном файле 600. Закрытый ключ остаётся на Рутокене. Сервер и агент не принимают пользовательский произвольный payload для подписи. По HTTPS работают все чувствительные соединения; reverse proxy доверяется только с localhost.


## Роли и реестр логистов

| Действие | Бренд-менеджер | Логист | Администратор |
|---|---|---|---|
| Накладные и исходные файлы | Только свои | Нет доступа | Все |
| Заказ КМ, отчёты | Только свои | Запрещено | Все |
| Просмотр реестра АТК всех сотрудников | Нет | Да | Да |
| Состав АТК, АТК/RESULT и их версии | Для своих групп | Все группы | Все |
| Массовое скачивание комплектов АТК | Нет | Да | Да |
| Заявки на трансформацию | Свои доступные АТК | Запрещено | Да |
| Согласования, подпись и настройки | Нет | Нет | Да |

Роль хранится в `users.role`, а не в теле запроса входа. Миграция 2 добавляет поле идемпотентно, с default `manager` и CHECK допустимых значений. Роль берётся из БД при каждом серверном запросе; при её изменении обычные сессии аннулируются. Административные права по-прежнему независимы от username и роли обычного входа.

Реестр использует отдельные GET `/api/logistics/atks` и `/api/logistics/atks/{id}`. POST `/api/logistics/download` только читает сохранённые файлы и формирует ZIP в памяти. Новых внешних операций этот маршрут не создаёт. Файлы общие на группу поставщика, поэтому ZIP устраняет повторы по group ID. Неполный комплект не скачивается. Статус архива определяется по связанным документам, включая дополнения из актуального снимка итоговых файлов.

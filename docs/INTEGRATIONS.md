# Реальные интеграции и проверенные схемы

Деморежимов приложения нет. Все runtime-клиенты выполняют настоящие HTTP-запросы к настроенным официальным хостам. HTTP transport подменяется только автотестами. Никакой код АТК не генерируется приложением; он принимается из фактической вложенности КМ в ГИС МТ после успешного документа.

## Методы

Базовые адреса: `BM_OMS_URL=https://suzgrid.crpt.ru`, `BM_TRUE_URL=https://markirovka.crpt.ru`. Хосты проверяются: HTTPS, только домены `crpt.ru` / `crptech.ru`, без userinfo, пути и query. Произвольный URL через пользовательский API не принимается.

| Операция | Метод и путь | Успех |
|---|---|---|
| Challenge | GET `/api/v3/true-api/auth/key` | `uuid`, `data` |
| Авторизация ГИС МТ | POST `/api/v3/true-api/auth/simpleSignIn` | `uuidToken`, не legacy JWT `token` |
| Авторизация СУЗ | POST `/api/v3/true-api/auth/simpleSignIn/{omsConnection}` | `token` |
| Сведения о КМ / АТК | POST `/api/v3/true-api/cises/info?pg=radio` | Все запрошенные `cisInfo`, проверка собственника/статуса |
| Эмиссия | POST `/api/v3/order?omsId=…` | `orderId`; сам ID не означает готовность |
| Готовность | GET `/api/v3/order/status?omsId=…&orderId=…` | Буфер нужного GTIN `ACTIVE`, `availableCodes` |
| Получение КМ | GET `/api/v3/codes?omsId=…&orderId=…&gtin=…&quantity=…` | `blockId`, `codes`; **расходует буфер**, автоматически не повторяется |
| Список блоков | GET `/api/v3/order/codes/blocks?omsId=…&orderId=…&gtin=…` | `blocks` того же заказа и GTIN |
| Восстановить конкретный блок | GET `/api/v3/order/codes/retry?omsId=…&blockId=…` | Тот же `blockId`, `codes`; ограничения §4.4.6.1 |
| Нанесение | POST `/api/v3/utilisation?omsId=…` | `reportId`; далее отдельные проверки |
| Статус отчёта | GET `/api/v3/report/info?omsId=…&reportId=…` | `reportStatus=SUCCESS` |
| Квитанция | GET `/api/v3/receipts/receipt?omsId=…&resultDocId=…` | Соответствующий `resultDocId`, `state=SUCCESS`, `code=0` |
| Создание / трансформация АТК | POST `/api/v3/true-api/lk/documents/create?pg=radio` | Строка внешнего ID документа |
| Состояние / квитанция документа АТК | GET `/api/v4/true-api/doc/{docId}/info?pg=radio&body=true&content=true` | Тот же ID, `CHECKED_OK`, отсутствие ошибок и подтверждённая фактическая вложенность |

СУЗ: `clientToken`, `X-Signature` для подписываемого тела, `Content-Type: application/json;charset=UTF-8`. True API: `Authorization: Bearer …`. HTTP redirect отключён, транспорт не повторяет запросы автоматически. Неожиданный ответ мутации означает неизвестный результат.

## Сохранённые тела

### Заказ

```json
{
  "productGroup": "radio",
  "products": [{"gtin": "<14 цифр>", "quantity": 1, "serialNumberType": "OPERATOR", "templateId": 36, "cisType": "UNIT"}],
  "attributes": {"releaseMethodType": "IMPORT", "paymentType": 1, "productionOrderId": "<внутренняя связь заказа>"}
}
```

`paymentType: 1` находится в `attributes`, как описано в таблице 45 руководства. Доступность оплаты по эмиссии для конкретного GTIN зависит от его группы внедрения оплаты; отказ СУЗ не подменяется другим способом оплаты.

### Отчёт о нанесении

```json
{
  "productGroup": "radio",
  "sntins": ["<полный исходный КМ>\u001d30<количество конкретного КМ>"],
  "attributes": {"productionDate": "<ГГГГ-ММ-ДД>", "kpp": "<9 цифр>"}
}
```

Опциональный `fiasId` включается при заполнении. В качестве единицы используется `UNIT`, поэтому дата производства нужна; для юридического лица требуется КПП места деятельности. `REAPPLY`, `DIVISIONMARK` и `SPLITMARK` здесь не используются. Дата не выдумывается и не подставляется автоматически.

### АТК

Тело: `trade_participant_inn`, `products_list: [{ki: "<КИ>"}]`. Обёртка: `document_format: "MANUAL"`, `product_document` — Base64 точных UTF-8 байтов, `type: "ATK_AGGREGATION"`, `signature` — откреплённая подпись в Base64.

Для трансформации тело дополнительно содержит `atk` и `transformation_type: "ADDING"` либо `"REMOVING"`, тип обёртки — `ATK_TRANSFORMATION`.

Перед отправкой: `APPLIED`, наш собственник, тип эмиссии `FOREIGN`, допустимое особое состояние, полный ТН ВЭД совпадает с накладной, отсутствие другого родительского агрегата. Для изъятия допускается только ожидаемый текущий родитель. Сам АТК перед трансформацией также проверяется: `APPLIED`, без особого состояния либо `FTS_RESPOND_NOT_OK`.

Официальное общее правило группирует по первым четырём цифрам ТН ВЭД. Приложение намеренно выполняет более строгое **согласованное бизнес-правило по всем десяти цифрам**. Автоматического разбиения по 30000 нет; ограничение API приводит к видимой ошибке.

После успешного создания АТК сервер повторно запрашивает все КИ: их `parent` должен быть одним и тем же 25-символьным кодом (20 цифр и 5 цифр/латинских букв с учётом регистра). После трансформации проверяется фактическое добавление/изъятие, а не только получение внешнего ID. Приложение не извлекает АТК из недокументированных предположений о поле ответа.

## Ввод в оборот · Импорт с ФТС

Сверено с [официальным True API](https://docs.crpt.ru/gismt/True_API/), v749.0 от 29.10.2026, §4.1.4.8 (30.10.2026).

Используется `POST /api/v3/true-api/lk/documents/create?pg=radio`, `document_format=MANUAL`, `type=LP_FTS_INTRODUCE`, Base64 точных подписанных UTF-8 байтов и откреплённая УКЭП. Тело:

```json
{"trade_participant_inn":"<ИНН>","declaration_number":"XXXXXXXX/ДДММГГ/XXXXXXX","declaration_date":"YYYY-MM-DD","products_list":[{"atk":"<АТК из ДТ>","children":[{"cis":"<КИ>","tn_ved":"<10 цифр из строки накладной>","production_country_code":"156"}]}]}
```

Передаются целые АТК с вложенными КИ, без дублирования агрегата и вложений на верхнем уровне. Каждая строка КИ явно содержит полный ТН ВЭД. Состояние проверяется существующим `GET /api/v4/true-api/doc/{id}/info`, затем все КИ перечитываются через `cises/info`. Одного `CHECKED_OK` недостаточно: завершение возможно только при `INTRODUCED` всех КИ и собственнике с настроенным ИНН. Отрицательное решение ФТС блокирует завершение; ожидающие КИ остаются на проверке. Область документа и версии АТК фиксируются снимком до подписи. Общие АТК завершают все связанные накладные одной операцией.

Автотесты используют транспорт с подменой ГИС МТ. Реальные документы с УКЭП в продуктив не отправлялись.

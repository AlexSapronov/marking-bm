# Аудит текстов UI и соответствия бизнес-операциям

Основание: ревизия интерфейса по issue #33, замечание о преждевременных статусах «Готово» и «У логиста». Проверены рендеринг, обработчики `data-action`, обработчики форм, маршруты `main.py` и переходы `Service`. Перечень охватывает кнопки основных рабочих мест ОБМ, логиста и администратора, включая глобальную навигацию. Это **проверка программной логики**, а не подтверждение реальной доставки, подписи и обработки во внешних системах.

## Словарь этапов накладной

| Техническое состояние | Показываемый смысл | Что действительно произошло |
| --- | --- | --- |
| `draft` | Черновик | Состав ещё подготавливается |
| `ordering` / `receiving` | Заказ / получение КМ | Идёт получение полного набора кодов; готовности этикеток ещё нет |
| `ready` | Этикетки готовы | Сформирована текущая версия этикеток; нет доказательства передачи поставщику |
| `transferred` | Ожидает нанесения | Сотрудник **отметил** передачу текущей версии этикеток; система не подтверждает физическое получение поставщиком |
| `reporting` | Отчёт о нанесении в обработке | Отчёт создан/ожидает подписи/отправки либо обработки |
| `reported` | Отчёт принят | Подтверждён результат отчёта, но итоговые АТК/RESULT ещё не гарантированы |
| `aggregating` | Формирование АТК | Итоговые документы ещё создаются |
| `done` (накладная) | **Комплект сформирован** | Сформированы АТК и RESULT; **не подтверждены** приёмка логистом, сборка физического груза, отгрузка, доставка или закрытие |
| `archive` | В архиве | Накладная архивирована; основание может быть закрытие логистом, принудительная остановка или шестимесячный механизм, пока не доработан #41 |
| `done` (операция) | Завершена | Внешняя операция завершена, но не весь документооборот накладной |
| `done` (АТК) | АТК сформирован | Сформирован АТК, но готовность пары файлов АТК + RESULT определяется отдельно по `download_ready` |

Не используем «Груз сформирован», «В пути» и «Принято логистом» для `done`: в базе нет факта физической сборки, передачи, перевозки либо принятия логистом. Для этих событий необходимы отдельные подтверждения/статусы, а не замена подписи.

## ОБМ: рабочий реестр и карточка

| Контрол / кнопка | Реальный эффект | Что важно сотруднику |
| --- | --- | --- |
| Накладные / Архив | Переход между рабочими и архивными документами | Не закрывает и не перемещает накладную |
| Новая накладная → Создать черновик | Создаёт черновик после заполнения обязательных реквизитов | Не заказывает КМ |
| Загрузить Excel | Импортирует данные в редактируемый состав/предпросмотр | Не публикует состав и не заказывает коды до сохранения |
| Скачать шаблон Excel | Скачивает шаблон | Не изменяет данные |
| Добавить строку / удалить строку | Только локальное редактирование состава | Требуется сохранение; несохранённые изменения помечаются |
| Проверить и сохранить состав | Проверка/предпросмотр различий и сохранение после подтверждения | Данные PN/GTIN и количество могут измениться; до отчёта допускается перенос |
| Заказать КМ → подтверждение | Подбирает свободные КМ и создаёт заказ для нехватающих | Подпись, получение и внешняя обработка выполняются позже; деньги списываются при эмиссии новых КМ |
| Скачать ZIP с этикетками · версия | Скачивает текущую версию этикеток | Это не печать и не регистрация факта передачи |
| Подтвердить передачу этикеток | Фиксирует в журнале локальное подтверждение передачи конкретной версии поставщику | Не доказывает физическое получение, не отправляет отчёт в СУЗ |
| Подтвердить нанесение и создать отчёт | Открывает диалог с фактической датой производства; по подтверждению создаётся отчёт в очереди подписи | Не означает немедленного успешного нанесения в ЧЗ |
| Подтвердить нанесение и создать отчёты | То же для выбранных накладных | Выбор через страницы виден целиком; до 200 АТК ограничение относится к скачиванию, не к этому действию |
| Повторить отчёт о нанесении / создать повторный отчёт | Создаёт **новую** операцию только после безопасных проверок отказа/частичной обработки | Нельзя заново отправлять уже нанесённые КМ |
| Перенести строки и КМ | Предпросмотр остатков и перенос между накладными одного поставщика | Доступно до отчёта/АТК, сервер перепроверяет безопасность |
| Загрузить существующий PDF (админ) | Прикрепляет файл к специальному сценарию архивных этикеток | Не создаёт КМ и не отменяет ранее выданные версии |
| Создать дополнение | Открывает создание отдельного документа-дополнения | Не меняет исходную накладную напрямую |
| Остановить и архивировать | После ввода номера останавливает дальнейшую локальную обработку и архивирует | **Не отзывает** уже отправленные операции, не возвращает стоимость эмиссии |
| Вернуть из архива (админ) | Восстановление с обязательной причиной | У внешних операций могут оставаться неизвестные результаты |
| Обновить состояние | Обновляет данные накладной с сервера | Не повторяет внешнюю отправку |
| Вкладки Состав / Обработка и файлы / История | Показывают разные части одного документа | Не выполняют операций |

## Логист: АТК, RESULT и закрытие

| Контрол / кнопка | Реальный эффект | Что важно сотруднику |
| --- | --- | --- |
| Реестр АТК / обновить реестр | Открывает или перезагружает записи всех сотрудников | Не означает принятие комплекта логистом |
| Поиск, фильтры, сортировка, страницы | Только локальный просмотр/фильтрация данных | При применении фильтров выделение для ZIP сбрасывается с предупреждением |
| Открыть код АТК | Показывает комплект, накладные, состав КМ, актуальные и прежние версии файлов | Не закрывает документ |
| Кнопка «Открыть для закрытия накладных» в строке АТК | Открывает **карточку АТК**, где доступны индивидуальные действия | Бывшая «Завершить накладные» неверно обещала массовое завершение |
| Скачать АТК / RESULT · версия | Скачивает конкретный файл | Факт скачивания не является фактом приёмки, отгрузки или доставки |
| Выбрать АТК / Скачать ZIP | Скачивает плоский архив готовых комплектов (макс. 200 АТК) | Групповые файлы не дублируются; скачивание не меняет бизнес-состояния |
| Закрыть накладную (в карточке АТК) | Открывает подтверждение отдельной накладной | Только после проверки доступности всех файлов |
| Закрыть накладную в архив | Вызов `POST /api/logistics/documents/{id}/complete`: переводит `done → archive` | Это **локальное закрытие**; подтверждения доставки/приёмки груза нет |
| Архивные АТК | Показывает записи по архивным документам | Причина архивирования может отличаться, см. #41 |

## Администратор

| Контрол / кнопка | Реальный эффект / ограничение |
| --- | --- |
| Добавить сотрудника | Создаёт учётную запись, выдаёт код первичной установки пароля |
| Сменить роль | Меняет серверную роль; права, сессии и отображаемые модули обновляются по ACL |
| Отключить / включить | Меняет доступ; отключение с подтверждением завершает сеансы, но не удаляет накладные |
| Сбросить пароль | Инвалидирует старые сеансы, выдаёт новый одноразовый код |
| Запросить обновление доступа ГИС МТ/СУЗ | Создаёт операцию авторизации **в очередь подписи** на Windows-ПК; это не готовый токен |
| Сохранить настройки | Сохраняет параметры организации/эмиссии; не отправляет отчёты |
| Сменить ответственного | Меняет владельца накладной, сохраняет историю, не передаёт её внешнему поставщику |
| Возобновить локальное задание | Повторно ставит в очередь только подтверждённый локальный сбой **до внешней отправки** |
| Создать повторный отчёт | Создаёт новую операцию после сверки частичной/отклонённой обработки |
| Повторить предпроверку | Для `preflight_blocked` возвращает операцию в очередь на повторную проверку; **не утверждает**, что внешняя отправка уже прошла |
| Запросить проверку статуса | Возвращает/ставит задачу в очередь повторной сверки с известным внешним ID; не является синхронным ответом ЧЗ |
| Восстановить блок СУЗ | Сверяет и привязывает уже полученный блок; не повторяет исходный запрос получения |
| Указать ID после сверки ЛК | Связывает неизвестный результат с внешним ID после проверки; не выполняет повторную отправку |
| Скрыть / вернуть предупреждение | Меняет видимость предупреждения с обязательной причиной; техническое состояние внешней операции не меняется |
| Рассмотреть трансформацию | Показывает точный состав, позволяет согласовать/отклонить с причиной; согласование запускает дальнейшую обработку, а не мгновенно изменяет внешний АТК |
| Разрешить подбор изъятого КМ | Разрешает ограниченный повторный подбор после проверок и фиксации причины; не означает мгновенное включение в АТК |
| Исправить привязку ТН ВЭД | Сохраняет корректировку справочника; исторические документы остаются с прежними данными |
| Изменить / объединить поставщика | Редактирует имя или объединяет записи; объединение имеет отдельное предупреждение о затрагиваемых ссылках документов |
| Импортировать архивную накладную | Предпросмотр КМ, проверки наличия в системе и владельца, далее локальный импорт; заказ новых КМ и PDF не создаётся |
| Журнал действий / фильтры / обновить админку | Только просмотр и перезагрузка данных |

## Выявленные системные вопросы (не маскировать текстами)

1. **#41:** автоматическое архивирование старого `done` может обходить явное закрытие логистом. Нужен пересмотр регламента, не только подписи кнопки.
2. Отсутствуют независимые зафиксированные события «груз физически собран», «принят логистом», «в пути», «прибыл», «приёмка склада подтверждена». Названия стадий нельзя строить так, словно эти события уже наступили.
3. Закрытие логистом не требует доказательства скачивания ZIP или логистического подтверждения. Сервер проверяет готовность АТК/RESULT, но не фактическую доставку. В интерфейсе это прямо оговорено.
4. Недоступные кнопки и checkbox ещё не везде имеют постоянные (без наведения) объяснения. Требуется отдельный проход ACL/disabled-сценариев в #33.
5. Админские пользователи, справочники и аудит не во всех случаях используют одинаковые страницы/сортировку. Часть истории ограничена последними данными из API.
6. Специальный импорт исторических документов имеет собственный браузерный `confirm()`, помимо предпросмотра. Сценарий заслуживает отдельного шага унификации и регрессионной проверки.
7. Цикл реального склада/ТСД, таможни и отгрузки не должен описываться текстом текущего `marking-bm`, если событие не записано в соответствующем модуле.

- CI: `ruff`, `node --check`, `pytest`, `tests/browser_smoke.py`.
- Браузерные сценарии для ОБМ, логиста, администратора, светлой/тёмной темы, десктопных размеров 1366×768, 1920×1080, 2560×1440.
- Regression smoke различает кнопку **открытия карточки АТК** и **реальное закрытие накладной**, проверяет нейтральный статус сформированного комплекта.
- До реальной производственной приёмки дополнительно проверить на рабочем месте реальные юридические/физические этапы и соответствие должностным инструкциям.

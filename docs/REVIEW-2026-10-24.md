# Ревью и готовность к корпоративному пилоту · 24.10.2026

Проверен marking-bm на базе `b99d766b6031dc3a215f8f07b862485ecf3ec06b`: API, разграничение ролей и владельцев, очередь и восстановление внешних операций, генерация/хранение файлов, импорт Excel, резервное копирование, браузерные сценарии, конфигурация systemd/nginx и исходники Windows-подписанта. Это ревью исходников и локальных тестов; рабочий VPS, его сеть и конкретный корпоративный Windows-ПК из этой среды не проверялись.

## Подтверждённые проблемы и исправления

Восемь новых регрессионных сценариев сначала воспроизвели ошибки исходной версии, затем прошли после исправлений. Полный набор: 97 pytest-тестов и Chromium smoke; Ruff F и синтаксис JS. Внешние сервисы подменяются только внутри тестов. Продуктивные операции ЧЗ из среды разработки не выполнялись.

Существующая логика завершения накладной логистом и переноса в архив сохранена. Миграций и изменений статусов по отменённому запросу о рассинхроне нет.

## Вывод о запуске

**После применения исправлений проект подходит для контролируемого корпоративного пилота. Без проверки на рабочем сервере и конкретном ПК объявлять безусловную готовность к промышленной эксплуатации нельзя.**

| Компонент | Оценка |
|---|---|
| Ubuntu VPS | Реализация есть: Python 3.12, закреплённые зависимости, systemd, nginx, SQLite WAL, backup/restore. Установку и HTTPS на сервере выполняет ответственный с административным доступом. |
| Закрытая корпоративная сеть | Вход из интернета не требуется. VPS должен иметь разрешённый исходящий HTTPS к настроенным ГИС МТ/СУЗ; полностью изолированный сервер без такого маршрута работать с ЧЗ не сможет. |
| Windows 10 Pro без прав администратора | Сам подписант запускается из профиля пользователя: Windows PowerShell и штатный `cscript.exe`. Python, WSL и права администратора для его обычного запуска не нужны. КриптоПро/CAdESCOM и драйвер Рутокена должны быть заранее установлены и исправны. |
| Политики Windows | IT должен разрешить эти два скрипта, PowerShell и Windows Script Host. При AllSigned может понадобиться подпись скрипта, при блокировке WSH — разрешение IT. Самостоятельный обход политик не является способом установки. |
| Доступность подписи | Пока ПК выключен, спит либо Рутокен/ключ недоступен, задания ждут. Для круглосуточной работы нужна соответствующая доступность подписанта; текущий пользовательский процесс сам этого не гарантирует. |
| Подтверждение на рабочем месте | Локальный `-Diagnose` обоих форматов, затем связь с VPS, авторизация и согласованный владельцем первый реальный сквозной документ. В Linux невозможно подтвердить работу физического Рутокена и корпоративных политик. |

Обязательное условие принятой модели доступа: обычные сотрудники входят по username без пароля. Это сознательная бизнес-настройка, а не подтверждение личности; закрытая сеть сама по себе не делает аудит достоверной идентификацией человека. В пилоте нужна согласованная доверенная группа пользователей. Для будущей общей ERP следует отдельно спроектировать корпоративную идентификацию/SSO и права модулей, не объявляя текущий вход эквивалентом доменной аутентификации.

## Что проверить перед первым рабочим документом

1. Согласовать с IT внутренний HTTPS URL, доверие сертификату на обоих узлах и исходящий доступ VPS к ЧЗ. Порт приложения остаётся на localhost; один worker Uvicorn, один экземпляр обработчика на БД.
2. Установить подписант из одной версии: `Start-Signer.ps1` и `Sign-Payload.vbs`. Сертификат с доступным закрытым ключом — в `CurrentUser\My` фактического пользователя. IT проверяет лицензию и доверие цепочке сертификата, доступ к проверкам отзыва, политики скриптов.
3. Выполнить `-Diagnose` от обычного пользователя; проверить оба формата подписи, штатный PIN/касание, работу после блокировки/разблокировки ПК. Затем проверить heartbeat и авторизацию. Не создавать платные заказы ради проверки связи.
4. Настроить backup вне единственного диска VPS и проверить восстановление в изолированную копию с отключённой внешней отправкой. Не запускать две активные копии одной восстановленной БД с одним доступом ЧЗ.
5. Выполнить согласованный первый документ и сверить ЛК ЧЗ, квитанции, итоговые файлы и чтение напечатанного DataMatrix. Включение `BM_ALLOW_EXTERNAL_WRITES` может обработать уже существующую подписанную очередь — её состав нужно проверить заранее.

`/health` подтверждает ответ HTTP-приложения, но не доступность ЧЗ, подписанта или успешность эмиссии. Для эксплуатации проверять также очередь, heartbeat, ошибки обработчика, свободный диск и дату последнего backup.

## Windows 10 и внешние источники

На дату ревью стандартная поддержка Windows 10 Pro 22H2 завершена 14.10.2025. Для рабочего ПК IT должен подтвердить применимую программу ESU/обновлений или согласовать поддерживаемую ОС. Совместимость скрипта с Windows 10 не равна поддержке безопасности самой ОС.

- [Microsoft: окончание поддержки Windows 10](https://learn.microsoft.com/en-us/lifecycle/announcements/windows-10-end-of-support).
- [Microsoft: ESU для Windows 10](https://support.microsoft.com/en-us/servicing/os/windows-10/2025/10/windows-10-extended-security-updates-esu-program).
- [Microsoft: приоритет корпоративных политик PowerShell](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies/).

Это не независимый пентест, нагрузочное испытание или проверка безопасности всех сторонних зависимостей. Итоги относятся к перечисленным сценариям. Менеджер Национального каталога в это изменение не входит.

# Приёмка

## Автоматические проверки

```bash
python -m pytest -q
python tests/browser_smoke.py
```

Проверяются импорт/контрольные цифры/объединение, глобальные конфликты, подтверждение разницы, конкурентное резервирование, общий пул разных поставщиков, изменение AI 30, частичное получение, изоляция username/admin/signer, CSRF, leases/replay, отдельные отчёты, независимые группы поставщиков, настоящие схемы запросов к мокам транспорта, АТК/RESULT, согласования, дополнения, неизвестные результаты, восстановление блока, потеря связи/рестарт, календарный архив, backup/restore. Обе формы DataMatrix реально декодируются ZXing из растеризованного PDF; проверяется размер страницы 58×40 мм.

Браузерная проверка использует обычное приложение и реальный Chromium. Она не заказывает коды: внешняя отправка выключена. Моки HTTP есть только в автотестах; приложение не содержит альтернативного деморежима.

## Перед первой реальной операцией

1. Владелец явно разрешает конкретную накладную, состав и минимальный платный заказ. До этого не выполнять платные операции.
2. Сверить карточку товара, GTIN, десятизначный ТН ВЭД, метод `IMPORT`, допустимость `paymentType: 1`, место деятельности и дату производства. Убедиться, что у участника есть права импортёра и активные договоры.
3. Сделать backup, проверить восстановление в отдельный файл, остановить восстановленную копию. Работает только один продуктивный сервис/worker.
4. Выполнить `Start-Signer.ps1 -Diagnose` на настоящем Windows-ПК с Рутокеном. Зафиксировать PIN/касание, повторную подпись и поведение при блокировке ПК. Если COM недоступен или политика запрещает работу — остановиться; успешная подпись не имитируется.
5. Проверить HTTPS, время сервера и ПК, правильный сертификат/ИНН, сроки действия. Обновить токены и проверить heartbeat.
6. Включить внешнюю отправку только после проверки сохранённой очереди. Удалять/редактировать историю, чтобы скрыть прежние ошибки, нельзя.
7. Заказать согласованное минимальное количество КМ из реальной накладной. Зафиксировать внутренний ID, productionOrderId и внешний orderId; сверить в ЛК. Дождаться полного получения; проверить raw, GS, serial, криптохвост и AI 30 в PDF/RESULT.
8. Напечатать одну этикетку 100%, измерить 58×40 мм и считать физическим сканером. Подтвердить PN и количество, затем передать актуальную версию поставщику.
9. Отчёт запускать только после фактического нанесения. Сверить отдельный отчёт, квитанцию и `APPLIED` всех кодов в ЛК.
10. Проверить АТК, полный ТН ВЭД, 25-значный код из ЧЗ, его состав и сумму AI 30. Сверить оба Excel и полный список накладных.
11. Трансформацию проводить только при реальной необходимости, после отдельного согласования. Проверить квитанцию, актуальную вложенность, новые версии Excel и историю.

## Остановка при неопределённости

При потере ответа на заказ/отчёт/АТК не создавать новый документ для обхода блокировки и не повторять операцию в ЛК. Сверить IDs и фактический состав. Если найден единственный соответствующий документ — администратор привязывает внешний ID с причиной и запускает read-only проверку.

Если потерян ответ расходующего получения КМ, использовать только подтверждённый новый `blockId` в официальном восстановлении блока. При закрытом заказе метод может быть недоступен. В таком случае остановить обработку и обратиться в поддержку ЧЗ. Никакая новая эмиссия автоматически не компенсирует потерю ответа.

Платную эмиссию нельзя «откатить» удалением локального документа. Локальный backup нужен для восстановления приложения, а не для отмены уже выполненных внешних операций. После восстановления обязательна сверка внешнего состояния.

## Не выполнено в среде разработки

Нет реального Windows-ПК, Рутокена, PIN, сертификата и доступа организации к ЧЗ. Поэтому PoC физической подписи, реальная печать/сканирование и первая продуктивная цепочка требуют выполнения владельцем. Внешние мутации разработчик не выполнял. HTTP-контракты подтверждены документацией и тестами транспорта, но это не доказательство успешной продуктивной операции конкретной организации.

## Итоговая ручная UX-приёмка в корпоративной сети

Этот раздел не считается пройденным только от зелёного CI. Назначенный сотрудник должен проверить **каждое** из трёх рабочих мест на реальном корпоративном ПК (масштаб браузера 100%; десктопные окна **1366×768**, **1920×1080**, **2560×1440**) и отметить результат в протоколе приёмки.

| Проверка | ОБМ | Логист | Администратор |
| --- | --- | --- | --- |
| Первый вход, повтор пароля, обычный вход и выход | Да | Да | Отдельный административный пароль |
| Светлая/тёмная темы и сохранение выбора | Да | Да | Да |
| Основное действие на текущем этапе и правильный текст статуса | Да | Да | Да |
| Поиск, фильтры, сортировка, страницы, широкие таблицы | Накладные | АТК/RESULT | Пользователи/поставщики/операции/аудит |
| Недоступные действия имеют видимую причину и не обходят ACL | Да | Да | Да |
| Выбор для массовых действий между страницами, отмена | Отчёты | ZIP | Не применяется |
| Подтверждения и запрет потери несохранённых изменений | Да | Да | Да |
| Актуальная версия файла однозначно отделена от старой | PDF | АТК/RESULT | Аудит |
| Фактическое действие совпадает с текстом кнопки | Подтверждение передачи/отчёт | Открыть карточку/закрыть | Очередь, запрос проверки, повторный отчёт |
| Ошибки и неизвестный результат нельзя слепо отправить повторно | Да | Только чтение | Да |

**Проверка бизнес-смысла:** `documents.done` отображается как **«Комплект сформирован»**, не как «У логиста», «В пути», «Груз сформирован» или «Доставлено». Закрытие накладной в реестре логиста **не** означает фактическую доставку или складскую приёмку.

**Негативные сценарии:** отмена удаления доступа/слияния поставщиков/импорта; истёкший пароль или сессия; недоступный подписант; нет файла RESULT; неизвестный ответ СУЗ; повторное нажатие; возврат остановленной накладной только администратором.

**Фиксация:** для каждого экрана/разрешения запишите дату, версию коммита, браузер, исполнителя, пройдено/не пройдено, воспроизведение дефекта и ожидаемое поведение. Не включайте в скриншоты пароли, полные КМ, PIN, ключи или токены.

Текущие автоматические Chromium-тесты выполняются без внешней отправки. Для проверки продуктивных интеграций используйте отдельный согласованный план первой реальной операции, без создания дублей платной эмиссии. Шестимесячное автоархивирование без явного завершения логистом остаётся открытым вопросом [#41](https://github.com/AlexSapronov/marking-bm/issues/41).
